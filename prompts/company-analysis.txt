짧은 호출 연결 (기업 정보·거래관계 분석 Agent)

사용자는 아래 짧은 말만 보내면 된다. 경로는 실제 플레이북 문서 폴더를 기준으로 한다. 최초 문서 선택은 AGENTS.md를 따르고 이후에는 연결된 절만 다시 읽는다. 공식 요구사항·규정과 PLAYBOOK.md의 조사·합의·구현 승인 절차가 우선이다. 읽기 전용 검토 세션에서는 구현으로 전환하지 않는다.

[기업 분석 문제 같이 보자 / 거래관계 분석 문제 같이 보자]
읽을 곳: PLAYBOOK.md "조사·문제 정의 합의와 구현 승인", COMPANY_ANALYSIS.md 1~2절. 가져오기 확인은 QUICKSTART.md의 해당 절.
동작: 공식 지시·실제 데이터·기존 코드를 조사해 필수 질문, 기업 식별, 관계 의미, 데이터·도구 허용 범위와 완료 기준을 제시한다. 미확인 사항과 사용자 해석을 대조하고 합의한다. 주제명만으로 기능을 확정하거나 구현을 시작하지 않는다.

[기업 분석 구현 진행]
읽을 곳: PLAYBOOK.md "작업 흐름"·"작업 기록과 최종 보고", COMPANY_ANALYSIS.md 3~5절, VERIFICATION.md. 웹 UI가 필수이면 UI_ASSETS.md도 읽는다.
동작: 문제 정의가 합의된 뒤 받은 구현 승인 범위에서, 실제 입력으로 질문 → 조회·계산 → 근거 검증 → 응답을 연결하고 정상·예외를 검사한다. 일반적인 "구현 진행" 요청도 현재 과제가 기업 분석이면 이 항목으로 연결한다.

[기업 데이터 확인]
읽을 곳: COMPANY_ANALYSIS.md 1~2절, PLAYBOOK.md "조사·문제 정의 합의와 구현 승인".
동작: 원본을 읽어 키·결측·중복·참조·관계 방향·기간·단위를 확인하고 사실·가정·미확인을 구분한다. 이 호출 자체로 데이터 수정이나 외부 수집을 승인받은 것으로 보지 않는다.

[기업 분석 검증 보고]
읽을 곳: COMPANY_ANALYSIS.md 3~5절, VERIFICATION.md 1~4절.
동작: 기업 식별·수치·관계·출처·Agent 도구 실행의 검사 근거와 미검증 범위를 보고한다. 필요한 재검사는 기존 승인 범위에서 수행하고 모의 응답·실제 연결·사용자 화면 관측을 구분한다.

[기업 분석 제출 점검]
읽을 곳: COMPANY_ANALYSIS.md 5절, VERIFICATION.md 3~4절, QUICKSTART.md "중첩 Git과 사용한 지침의 제출 확인"·"환경에서 막힐 때".
동작: 실제 제출본·재실행·필수 질문별 결과·미검증 항목·사용한 지침의 포함 여부를 확인한다. 비공개 데이터·작업 기록은 공개 플레이북에 넣지 않으며 실제 제출 완료는 사용자가 확인한다.

이미 알려진 조건은 다시 묻지 않는다. 세션 재개 시 실제 승인 범위·미확정 목록·마지막 검증 결과를 확인하고 이어간다. 선택적 배치에서는 이 파일의 이름이 COMPANY_ANALYSIS_PROMPTS.txt다.

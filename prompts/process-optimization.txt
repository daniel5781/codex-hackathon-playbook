짧은 호출 연결 (최적화 과제 중심, 다른 과제에도 쓴다)

사용자는 아래 짧은 말만 보내면 된다. 에이전트는 해당 항목과 연결된 문서의 필요한 절을 읽고 처리한다. 경로는 플레이북 문서 폴더를 기준으로 하며, 문서의 최초 선택은 AGENTS.md를 따른다. 이미 알려진 정보는 다시 묻지 말고 필요한 원문·경로·종료 시각·허용 범위 중 빠진 것만 확인한다.
공식 규정·보안 제한과 PLAYBOOK의 승인 절차가 우선한다. 읽기 전용 검토 세션에서는 어떤 호출(구현 진행 포함)을 받아도 구현으로 전환하지 않고, 허용된 읽기·검토 결과만 대화로 보고한다.

[공정 문제 같이 보자]
읽을 곳: PLAYBOOK.md "조사·문제 정의 합의와 구현 승인", PROCESS_OPTIMIZATION.md 1~2절. 가져오기 확인은 QUICKSTART.md의 해당 절.
동작: 원문·실제 입력을 조사해 문제 종류와 모델 시트(비최적화면 요구사항 표)를 제시하고, 사용자 해석과 대조해 문제 정의를 합의한다. 아직 구현하지 않는다.

[구현 진행]
읽을 곳: PROCESS_OPTIMIZATION.md 2절의 승인 기준, PLAYBOOK.md "작업 흐름"·"알고리즘과 UI 개발 순서"·"작업 기록과 최종 보고", VERIFICATION.md. 최적화면 OPTIMIZATION.md 3~5절과 PROCESS_OPTIMIZATION.md 4~6절, 일정·배정이면 3절도 읽는다.
동작: 승인된 조건으로 작은 실제 동작부터 구현·검증한다. 핵심 가정의 미확정 처리는 PROCESS_OPTIMIZATION 2절을 따르고, 긴 계산은 OPTIMIZATION 8절을 따른다.

[검증 보고]
읽을 곳: VERIFICATION.md 1~4절, 최적화 결과가 있으면 PROCESS_OPTIMIZATION.md 5절.
동작: 현재 결과·검증 근거·미검증 범위·사용자가 정할 것을 보고한다. 필요 재검사는 기존 승인 범위에서 수행한다. 설치 테스트 등 일부 검사의 통과를 전체 모델·알고리즘의 지침 준수로 보고하지 않는다.

[해 없음 확인]
읽을 곳: PROCESS_OPTIMIZATION.md 5절, 시간 제한으로 미결이면 OPTIMIZATION.md 8절.
동작: 종료 상태를 가르고, 불가능 증명이면 원문과 제약을 대조해 모순 원인을 확인한다. 미확보 상태면 남은 시간 안에서 실행 가능성 탐색을 검토한다.

[시간 점검]
읽을 곳: PLAYBOOK.md "자원 사용", OPTIMIZATION.md 8절.
동작: 현재·마감 시각, 검증된 저장 결과와 미해결 부분, 조합 검증 상태, 남은 작업의 우선순위를 보고하고 합의한 범위에서 이어서 진행한다.

[제출 점검]
읽을 곳: VERIFICATION.md 3~4절, QUICKSTART.md "중첩 Git과 사용한 지침의 제출 확인"·"환경에서 막힐 때".
동작: 실제 제출본의 형식·재실행·필수 검사·사용자 관측·지침 포함 여부·비밀정보·남은 한계를 확인한다. 구현 완료·검증 통과·실제 제출 완료를 구분한다.

추가 요청도 해당 절로 연결한다: 내 해석과 대조 → PROCESS_OPTIMIZATION 2절, 담당자 답 반영 → PLAYBOOK "담당자 추가 요청 관리", 너무 쉬운 해 확인 → PROCESS_OPTIMIZATION 5절.
세션 재개 시에는 작업 기록의 실제 승인 범위·미확정 목록·마지막 검증 결과를 확인하고 이어간다. 재개 요청 자체로 미확정 조건을 승인된 것으로 바꾸지 않는다.

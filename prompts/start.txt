현재 과제 README·공식 요구사항·기존 지침을 우선 확인해줘.
과제 루트와 지침 경로를 구분해줘. 선택적 setup.sh가 안내한 경로가 없으면 기본 위치는 과제 루트의 playbook/이며, 없을 때만 공개 저장소 https://github.com/daniel5781/codex-hackathon-playbook 을 Clone해줘. 이미 있으면 내용·원격·Git 루트·변경 상태를 확인하고 덮어쓰기·임의 pull·reset·삭제는 하지 마. 구현·실행은 과제 루트에서 하고 기본 시작에는 setup.sh를 실행하지 마.
기본은 playbook/AGENTS.md와 playbook/prompts/start.txt를 명시적으로 읽어줘. 선택적 setup.sh가 안내한 경로가 있으면 그 폴더의 AGENTS.md와 START_PROMPT.txt를 읽어줘. 이미 읽은 시작 파일은 반복해서 읽지 마. 최적화 과제는 OPTIMIZATION.md, 웹 UI 과제는 UI_ASSETS.md를 실제로 읽고 둘 다 해당하면 둘 다 읽어줘. 무관한 문서는 생략하고 상대경로는 실제 플레이북 위치를 기준으로 해석해줘. UI 지침은 외부 라이브러리 도입을 의무화하지 않아.
시작에 한 번만 실제로 읽은 문서 경로·확인한 플레이북 커밋 버전 / 선택·생략한 문서와 이유 / 적용할 원칙 2개를 짧게 보고해줘. 미커밋 변경을 구분하고 버전 확인이 안 되면 미확인이라고 적어줘.
구조와 핵심 기술 선택을 짧게 설명하고 중요한 판단만 질문해줘. 기존 스택으로 MVP → 실행·검증 → 필수 기능 확장 → 오류 수정 → 제출 확인까지 진행해줘.
주요 기능은 무엇·이유·실제 검증으로 보고하고, 제출 전 기술 선택 이유·AI 제안 검토 사례·검증 근거를 정리해줘.
완료 시 기존 작업 기록에 적용 지침 → 실제 변경 파일·함수 → 실행 명령·결과를 연결해줘. 읽지 않은 문서를 읽었다거나 계획만 한 작업을 적용했다고 보고하지 마.

# codex-hackathon-playbook

Codex가 **요구사항 분석 → 설계 → 구현 → 테스트 → 검증 → 제출 준비**를 일관되게 수행하도록 돕는 한국어 개발 지침이다. 특정 언어나 프레임워크에 의존하지 않으며, 실제 파일 수정과 실행 증거를 중심으로 구성했다.

SK하이닉스 AI 해커톤 2차 예선을 준비하며 만든 개인용 범용 자료다. 공식 운영 지침은 아니며, 아래 환경 제약은 준비 시 제공받은 조건을 반영했다. 실제 과제의 README와 최신 공식 요구사항을 우선 확인하라.

**바로 시작하려면 [QUICKSTART.md](QUICKSTART.md)를 사용하라.** 제공된 Codex에 공개 저장소를 Clone하고 과제 루트에 세팅하도록 요청할 수 있다. [세팅 스크립트](scripts/setup.sh)는 기존 파일을 보존하며 범용 지침과 시작 프롬프트만 배치한다.

## 파일별 역할

| 파일 | 역할 | 읽는 시점 |
| --- | --- | --- |
| [AGENTS.md](AGENTS.md) | Codex의 기본 행동, 환경 제약, 실행·검증·보고 규칙 | 작업 시작 시 |
| [PLAYBOOK.md](PLAYBOOK.md) | 7단계 개발 절차, 단계별 프롬프트, 의사결정·테스트 기록 양식 | 해당 단계가 필요할 때 |
| [README.md](README.md) | 적용 방법, 자동 지침의 범위, 사용 시 주의사항 | 최초 적용 시 |
| [QUICKSTART.md](QUICKSTART.md) | 시험 안에서의 Clone·세팅·실행 확인 순서 | 시험 시작 시 |
| [UI_ASSETS.md](UI_ASSETS.md) | 기존 UI 분석, 공개 에셋 선택·통합·검증·출처 기록 | 대시보드·웹 UI 과제일 때만 |
| [scripts/setup.sh](scripts/setup.sh) | 기존 파일을 보존하는 문서 배치 스크립트 | 환경에 적용할 때 |
| [prompts/start.txt](prompts/start.txt) | 세팅 후 실제 구현·검증을 시작하는 요청 | 세팅 직후 |
| [tests/test_setup.py](tests/test_setup.py) | 재실행·충돌·기존 파일 보존 검사 | 스크립트 변경 시 |

## 새로운 프로젝트에 적용하기

1. 사전 개인 준비 환경에서 절차를 연습하라. 실제 시험에서는 허용된 공개 자료를 제공 환경 안에서 Clone·다운로드하라. 개인 PC의 파일 업로드나 외부 브라우저 직접 접근을 이용하지 마라.
2. 대상 프로젝트의 README와 기존 `AGENTS.md`를 먼저 읽어라. 기존 지침이 있으면 충돌하지 않는 항목만 병합하고, 없다면 프로젝트 루트에 이 저장소의 `AGENTS.md`를 배치하라.
3. 연결된 보조 문서 `PLAYBOOK.md`, `QUICKSTART.md`, `UI_ASSETS.md`도 같은 위치에 두되 필요한 단계·과제에서만 읽어라. 기존 동명 문서를 덮어쓰지 말고 다른 위치를 사용한다면 링크와 시작 프롬프트에 실제 경로를 적어라. 이 저장소의 README로 과제 README를 교체하지 마라.
4. Codex에서 **대상 프로젝트**를 작업 폴더로 열고 새 세션을 시작하라. 아래 프롬프트로 적용 지침과 요구사항을 확인한 뒤 구현을 진행하라.
5. 실제 의사결정과 테스트 결과는 허용된 로컬 작업 기록에 남겨라. 이 공개 저장소는 범용 지침만 유지하라.

공개 저장소 다운로드 예시(실제 시험에서 적용할 명령은 QUICKSTART를 참조):

```sh
git clone https://github.com/daniel5781/codex-hackathon-playbook.git
```

Codex 시작 프롬프트:

```text
현재 작업 경로와 적용되는 지침 파일을 확인해줘.
Computer Use는 절대 사용하지 말고 파일·터미널·프로젝트 테스트로만 작업해줘. GUI 확인은 내가 직접 할게.
과제의 공식 요구사항과 README를 우선하고 AGENTS.md를 따라줘.
PLAYBOOK.md는 필요한 단계만 참조해줘.
대시보드·웹 UI 과제라면 UI_ASSETS.md에 따라 기존 스택과 UI부터 확인하고 유리한 에셋만 선택적으로 재사용해줘.
필수 요구사항·제출물·완료 기준을 정리하고 기존 구조로 MVP를 구현해줘.
실제 실행과 정상·예외 입력, 관련 회귀 검증까지 진행하고 결과를 기록해줘.
중요한 선택은 이유를 알리고, 실행하지 않은 검사는 명확히 구분해줘.
실제 시험 환경에서는 Git Push와 시험 자료의 외부 전송을 하지 마.
후속 서술형은 AI 금지 단계이므로 답안 생성·수정을 돕지 마.
```

## AGENTS.md가 적용되는 범위

Codex는 시작할 때 지침을 찾는다. 기본 전역 위치는 `~/.codex`이며, `CODEX_HOME`을 지정했다면 그 위치를 사용한다. 프로젝트에서는 루트(보통 Git 루트)부터 현재 작업 디렉터리까지 확인한다. 루트를 찾지 못하면 현재 디렉터리만 확인한다.

각 위치에서는 `AGENTS.override.md`, `AGENTS.md`, 설정된 대체 파일명 순으로 비어 있지 않은 파일 하나를 선택한다. 전역부터 가까운 디렉터리 순으로 적용하며, 더 가까운 지침이 앞선 지침을 보완·재정의한다. 현재 디렉터리 아래의 모든 폴더를 자동 탐색하는 것은 아니다. 이는 파일 탐색 방식이며, 공식 요구사항보다 이 보조 지침을 우선하라는 뜻은 아니다. [공식 OpenAI 문서](https://learn.chatgpt.com/docs/agent-configuration/agents-md)

| 배치·상황 | 사용 방법 |
| --- | --- |
| 대상 프로젝트 루트에 `AGENTS.md` 배치 | 해당 프로젝트에서 시작한 Codex의 자동 탐색 대상이다. |
| 이 저장소를 다른 프로젝트 옆에 clone | 옆 폴더의 지침은 자동 적용되지 않는다. 대상 프로젝트에 병합하거나 프롬프트에서 경로를 명시하라. |
| `PLAYBOOK.md`만 배치 | 기본 자동 지침 파일이 아니다. `AGENTS.md` 또는 프롬프트로 필요한 절을 읽도록 요청하라. |
| 기존 지침을 수정할 수 없는 과제 | 허용된 로컬 위치의 문서 경로를 명시하여 보조 자료로 읽게 하라. 과제의 기존 규칙을 보존하라. |
| 작업 중 지침 추가·변경 | 새 세션에서 적용 파일을 확인하라. 현재 세션에서 즉시 필요하면 수정한 파일을 명시해 다시 읽도록 요청하라. |

예: `과제 규칙을 우선 유지하고, ../codex-hackathon-playbook/PLAYBOOK.md의 3~5단계를 보조 절차로 읽어 적용해줘.`

제공된 Codex 버전·설정에 따라 탐색 동작이나 길이 제한이 다를 수 있다. 적용 파일을 확인하되 이를 이유로 Codex를 업데이트하거나 전역 설정을 임의로 바꾸지 마라. 지침은 짧게 유지하고 상세 절차는 필요한 때 참조하라.

## 환경 제약과 주의사항

- **우선순위:** 과제의 공식 요구사항·README·기존 규칙이 이 저장소보다 우선이다. 상위 시스템·개발자 지침과 도구 권한도 준수하라.
- **버전·도구:** 제공된 Codex를 업데이트하지 마라. 허용된 AI 모델·도구만 사용하라. 공개 Skill·MCP·라이브러리도 필요한 경우에만 허용 범위를 확인하고 활용하라. MCP 서버나 복잡한 하네스를 불필요하게 구축하지 마라.
- **Computer Use 절대 금지:** 어떤 단계에서도 Computer Use로 브라우저·데스크톱 GUI를 자동 조작하지 마라. 파일·터미널·프로젝트 테스트로 작업하고 GUI 확인은 응시자가 직접 수행하라. 이는 사용자가 추가한 작업 제약이다.
- **자료 보호:** 시험 문제, 비공개 자료, 실제 제출물, 인증정보를 외부 검색·서비스·저장소로 보내지 마라. 제출물은 지정된 공식 제출 경로로만 제출하라. 실제 작업 로그도 이 공개 저장소에 추가하지 마라.
- **환경 유지:** 개인 API 키·유료 구독을 연결하거나 플랫폼 관리 설정·연결 프로세스를 변경하지 마라. 필요한 작업이 차단되면 제한을 우회하지 말고 제공 환경의 신고 경로를 이용하라.
- **시험 환경:** Git Push를 실행하지 마라. 제출은 GitHub 공개와 별개의 절차이며, 로컬 커밋도 공식 규칙과 사용자 요청이 허용할 때만 하라.
- **사전 개인 준비 환경:** 시험 환경의 Push 금지를 이 환경에 확대 적용하지 마라. 사용자가 요청한 범용 공개 지침·세팅 코드의 커밋·Push는 가능하다. 실제 시험 자료나 제출물을 섞지 마라.
- **검증과 기록:** 프롬프트 사용만으로 완료를 보장할 수 없다. 실제 명령·결과를 확인하고 성공·실패·미실행, 구현·검증·제출 상태를 구분해 보고하라.
- **후속 서술형:** 개발 작업 중 기록 정리에는 AI를 활용할 수 있다. 후속 서술형에서는 AI 사용과 복사·붙여넣기를 하지 말고 본인이 직접 답변하라.

언어별 도구 설치, 자동 배포, 외부 연동은 포함하지 않았다. 과제가 제공하는 실행 환경과 제출 방식에 필요한 범위에서만 적용하라.

세팅 스크립트를 변경했다면 개인 개발 환경에서 `bash -n scripts/setup.sh`와 `python3 -B tests/test_setup.py`로 검증하라. 실제 시험에서는 과제의 검증을 우선하고, 이 저장소를 시험 문제나 결과물의 백업 저장소로 사용하지 마라.
